# F02 raw evidence - (a) per-user reads and (b) global dump, no credentials

## a. Per-user reads (no credentials)

```
$ curl "http://127.0.0.1:8000/habits?username=testUser1"
$ curl "http://127.0.0.1:8000/habits?username=testUser2"
$ curl "http://127.0.0.1:8000/water?username=testUser1"
$ curl "http://127.0.0.1:8000/water?username=testUser2"
$ curl "http://127.0.0.1:8000/exams?username=testUser1"
$ curl "http://127.0.0.1:8000/exams?username=testUser2"
$ curl "http://127.0.0.1:8000/assignments/user/testUser1"
$ curl "http://127.0.0.1:8000/assignments/user/testUser2"
```
Every call above returned 200 with that user's data, with no Authorization header,
cookie, or token of any kind sent. Correctly scoped per the `username` query
param/path segment supplied - but that param is never verified against any
credential, so any caller can supply any username.

## b. Global dump (the actual unauthenticated, unscoped endpoint)

```
$ curl "http://127.0.0.1:8000/assignments"
```
This is the route with NO `username` parameter at all (`GET /assignments`, not
`GET /assignments/user/{username}` and not a `?username=` query string). It
returns every assignment for every user in one response:

```json
[
  {"title":"Lab05","course":"CMSC216",...,"username":"testUser1",...},
  {"title":"Proposal Draft","course":"ENGL393",...,"username":"testUser1",...},
  {"title":"Read Phil Article","course":"PHIL364",...,"username":"testUser2",...},
  {"title":"Homework","course":"STAT400",...,"username":"testUser2",...}
]
```
This confirms the database correctly separates assignments by `username`, but the
`GET /assignments` endpoint ignores ownership entirely - it has no per-user filter
at all, unlike the `a.` calls above which at least take a (trusted, unverified)
username. See `findings.md` F02(b) and `F02-ui-leak.txt` for how the frontend
Assignments page calls exactly this global route.
